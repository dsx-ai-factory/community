# Contributing to the DSX AI Factory Community Repository

Thank you for your interest in contributing. This repository publishes community
articles and hosts discussions about the open-source components of the NVIDIA DSX
AI Factory. Contributions are welcome from NVIDIA employees, partners, customers,
and the wider open-source community.

## What this repository is for

This repository is for **articles and discussion**, not for product source code.
The components themselves live in their own repositories in the
[`dsx-ai-factory`](https://github.com/dsx-ai-factory) organization.

Content that belongs here:

| Type | What it looks like |
| --- | --- |
| Component release post | What shipped, the problem it solves, major updates, what is next |
| Component or technology deep dive | The problem a component solves, how it works, architecture and technical detail |
| How-to | A step-by-step technical walkthrough, including versions, prerequisites, and commands |
| Success story | A customer, partner, or contributor showcase of what they built and the outcomes achieved |
| Event announcement or recap | Summary of NVIDIA event presence, announcements, and key takeaways |
| Exploratory post | Open-source philosophy, governance updates, how NVIDIA approaches a problem |
| Contributor spotlight | Who a contributor is, what they built, and what they learned |

Content that does **not** belong here: product documentation, install and user
guides, bug reports against a component, or support requests. Those belong with
the relevant component project.

## How to propose an article

1. **Open an issue or a discussion** describing the topic and audience before you
   write. This avoids two people writing the same piece.
2. **Fork the repository and open a pull request** with your article.
3. **A maintainer reviews and merges.**

Small corrections — typos, broken links, outdated version numbers — do not need a
prior issue. Open a pull request directly.

## Before you open a pull request

- Confirm nothing in your contribution is confidential, embargoed, or pre-release.
  Everything merged here becomes public. If you are unsure whether something is
  announceable, ask before opening the pull request, not after.
- Confirm you have the right to submit the content under this repository's license.
- Confirm any third-party material you quote or adapt is attributed, and that its
  license permits the use.
- Confirm any screenshots, logos, or images you include are cleared for public use.
- If your content mentions third-party trademarks or logos, add the required
  [trademark notice](#trademarks-and-logos) at the bottom.

## Signing Off Your Work

* We require that all contributors "sign-off" on their commits. This certifies that the contribution is your original work, or you have rights to submit it under the same license, or a compatible license.

  * Any contribution which contains commits that are not Signed-Off will not be accepted.

* To sign off on a commit you simply use the `--signoff` (or `-s`) option when committing your changes:
  ```bash
  $ git commit -s -m "Add cool feature."
  ```
  This will append the following to your commit message:
  ```
  Signed-off-by: Your Name <your@email.com>
  ```
